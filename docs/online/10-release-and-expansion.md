# 联机发布、扩展模板与版本整理

## 1. 目标

这份文档负责把 `L13-L15` 收成一套可重复执行的保守骨架：

- `L13`：联机测试环境、灰度、事故预案与发布说明统一收口。
- `L14`：后续新内容接入时默认复用现有 online runtime、房间状态机、结算凭证与五大面板。
- `L15`：把当前已落地能力、待补项、风险、灰度开关与最终验收口径整理成持续维护的版本视图。

当前策略仍保持：

- 默认 `stable + 全开`，不主动改变现有线上行为。
- 只有后台主动切到 `canary`、关闭模块或关闭单项能力时，发布闸门才会介入。
- 新内容优先复用现有系统，不另起第二套联机底层。

## 2. L13 当前收口

### 2.1 测试环境与灰度

当前已经有统一联机发布配置：

- `enabled`：联机测试环境总开关。
- `grayChannel`：`stable / canary`。
- `testWhitelist`：白名单测试账号。
- `featureFlags`：好友、庄园互访、求助单、节会房间四类小范围能力开关。
- `moduleSwitches`：`social / manor / order / festival / society` 五个模块级开关。

默认配置要求：

- `enabled = true`
- `grayChannel = stable`
- 各 `featureFlags = true`
- 各 `moduleSwitches = true`
- 白名单为空

这意味着：

- 老玩家默认继续走原有全开链路。
- 只有切到 `canary + whitelist` 时，未命中白名单的账号才会被挡在对应联机写路之外。
- 单独关闭模块时，只影响该模块，不应把其它联机主线一起拖下水。

### 2.2 事故预案

当前后台治理页已明确承接这些事故动作：

- 结算失败回滚：委托回滚、活动房间结算重放。
- 送礼失败补发：复用邮件补偿与活动奖励模板。
- 房间断线补偿：复用 `disconnect / reconnect` 和 `settling -> retry-close`。
- 公共事件重算：先切回 `stable`，再按 world-event 总览与 smoke 复核。
- 审核误伤恢复：复用误封恢复、图片隐藏回滚与现有举报处理面板。

### 2.3 发布说明

当前后台统一维护五类说明：

- 新功能说明
- 可见变化说明
- 玩家注意事项
- 已知问题说明
- 回退策略说明

要求：

- 发布说明只描述当前真的开放了什么。
- 如果某能力仍在 `canary` 或被模块开关关闭，说明里必须显式写清。
- 回退策略必须明确落回哪个开关或治理动作，而不是写成抽象口号。

## 3. L14 新内容接入模板

### 3.1 新庄园主题

最小接入要求：

- 提供 `theme_id`
- 提供主题一句话与展示标签
- 提供主视觉摘要
- 接到庄园页与主题周

不得绕开：

- 公开庄园快照
- 收藏 / 热门榜
- 主题周承接

### 3.2 新节庆接入

最小接入要求：

- 提供节庆定义与时间窗口
- 提供奖励池与纪念文案
- 指明是走节庆摊位、活动房间还是两者都走

不得绕开：

- 节会页入口
- 纪念册
- 统一发布说明

### 3.3 新房间玩法

最小接入要求：

- 提供房型 ID
- 指明成员上限
- 提供动作模板
- 提供逐成员结算写回
- 提供关闭条件与断线恢复口径

不得绕开：

- `08-room-state-machine.md`
- `07-state-and-settlement.md`
- 统一 receipt 与 close 语义

### 3.4 新村社工程

最小接入要求：

- 提供工程 ID
- 提供捐献包
- 提供阶段反馈与完工反馈
- 提供村社史册摘要

不得绕开：

- 公共建设进度
- 福利 / 世界反馈
- 村社史册回写

### 3.5 新委托类型

最小接入要求：

- 提供类型 ID
- 提供可见范围与交付字段
- 提供推荐理由与补偿口径

不得绕开：

- 求助单列表
- 结算凭证
- 补偿 / 审计 / 回滚链

### 3.6 新纪念品

最小接入要求：

- 提供来源事件
- 提供展示文案
- 提供名片、荣誉或纪念册挂点

不得绕开：

- 公开档案
- 纪念册
- 来源链可解释性

## 4. L14 扩展位约束

### 4.1 玩法扩展位

- 新职业标签：复用公开档案标签、推荐理由与热门展示。
- 新村社产业：复用村社主题、公共建设与福利解锁。
- 新世界事件：复用 world-event runtime、公共目标与世界纪年。
- 新公共建设：复用公共工程、贡献包与世界反馈。
- 新节会小游戏：复用活动房间状态机、动作模板与结算凭证。
- 新展示模板：复用庄园主题周、公开庄园布局与收藏入口。

### 4.2 经济扩展位

- 新交换品类：继续落在每周交换站 / 邻里寄售 / 节庆摊位。
- 新限量机制：继续复用价格带、频率限制、黑名单与治理快照。
- 新稀有来访池：继续复用关系标签、节庆窗口与公开展示。
- 新共同目标奖励池：继续复用公共目标阶段奖励与世界贡献回写。
- 新节庆代币池：继续复用节庆摊位、活动奖励与纪念层。

### 4.3 视觉扩展位

- 新庄园皮肤：挂到庄园主题与公开展示模板。
- 新访客名片背景：挂到公开档案与荣誉展示。
- 新村社徽记：挂到村社创建、公告与史册。
- 新节会舞台：挂到节会页与活动房间说明。
- 新纪念卡框：挂到荣誉系统、成就卡与纪念册。

## 5. L15 版本整理

### 5.1 当前已落地联机主线

- 庄园：公开快照、留言、来访、导览、收藏、主题周、展示模板。
- 邻里：名片、好友、关系标签、订阅、邻里治理。
- 委托：求助单、接单、交付、结算、互助声望、多段接力、推荐。
- 节会：节庆房间、世界事件、远征房间、纪念册、公共目标。
- 村社：组织、提案、投票、公共建设、公共仓、史册、共治。

### 5.2 当前待补项

- 更真实的 Presence 和推送订阅。
- 更完整的主视觉图、回放动画和深视觉差异。
- 更强的人审后台、精选流和运营图形化面板。
- 更完整的 UI 自动化、截图回归与深检索能力。

### 5.3 当前风险

- 新内容若绕开 receipt / compensation / audit，会重新引入跨玩家结算漏洞。
- 新慢交易内容若绕开治理快照，会重新引入通胀与刷写风险。
- 新实时玩法若另起房间底层，会把断线恢复和关闭语义打散。
- 新公开文本 / 图片入口若不同步接审核，会重新出现治理缺口。

### 5.4 当前灰度开关

- 总开关：`taoyuan_online_release_enabled`
- 通道：`taoyuan_online_gray_channel`
- 白名单：`taoyuan_online_test_whitelist`
- 小范围能力：好友 / 庄园互访 / 求助单 / 节会房间
- 模块开关：`social / manor / order / festival / society`

### 5.5 当前已知问题

- Presence 仍以最近活跃近似。
- 部分后台治理仍以 API + 统一治理面板承接，不是完整运营台。
- 部分历史 / 搜索 / 回放仍是轻量摘要，不是全量检索系统。

## 6. 阶段检查点

- 单人经营主循环仍保留在个人存档。
- 跨玩家奖励仍由服务端结算与补偿链承接。
- 联机入口已自然落进主菜单、地图与五大面板。
- 审核、限流、审计和治理后台已覆盖当前主要公开入口。
- 发布说明、灰度开关、样板模板和事故预案已有统一落点。

## 7. 最终验收口径

- 玩家能看见别人。
- 玩家能和别人往来。
- 玩家能和别人协作。
- 玩家能在节会里同场游玩。
- 玩家能参与村社治理。
- 玩家能在世界里留下痕迹。

当前第一轮判断：

- 以上六条都已具备最小可运行闭环。
- 后续继续扩线时，以“复用现有骨架”优先，不以“另起系统”优先。
